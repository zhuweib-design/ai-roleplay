# AI 酒馆 数据备份、恢复与灾备演练指南

> 对应全检报告 P2-#3「无自动化回滚流程，仅依赖用户手动备份文件」的修复交付：
> **文档化回滚路径 + 灾备演练 Runbook**。
> 本文档说明如何通过应用内置的「全量备份与恢复」能力，将应用数据回滚到历史某一时点，或跨设备迁移。

---

## 1. 为什么需要备份 / 回滚

AI 酒馆的所有数据（角色卡、对话、世界书、群聊、Persona、设置）默认存放在本地存储（Tauri 桌面为文件系统，Web 模式为 IndexedDB）。以下场景需要回滚能力：

- **误操作**：不小心删除角色卡 / 世界书 / 对话，或把配置改乱了。
- **升级异常**：应用大版本升级后数据结构不兼容或迁移出错。
- **设备损坏 / 换机**：需要把数据迁移到新设备。
- **内容污染**：对话被异常内容刷屏，需要回到干净时点。

本应用**不提供「一键自动回滚」按钮**（自动回滚在本地桌面应用中意味着后台覆盖用户数据，风险高且不可逆）。推荐做法：**定期手动导出备份文件，需要回退时用该文件导入覆盖**——导入即回滚。

---

## 2. 备份导出（如何做一份备份）

**入口**：设置 → 数据管理 → 全量备份与恢复 → `导出备份`

- **导出内容**：角色卡、对话、世界书、群聊、Persona、全局设置，序列化为**单一 JSON 文件**。
- **加密规则**：
  - 若已设置并**解锁主密码** → 导出为加密文件 `ai-roleplay-backup-YYYY-MM-DD.enc.json`（AES 加密）。
  - 若未设置主密码 → 导出为明文文件 `ai-roleplay-backup-YYYY-MM-DD.json`。
- **文件名**：`ai-roleplay-backup-<日期>.json` 或 `.enc.json`（日期为导出当天）。
- **安全护栏（重要）**：若当前设置里存在**明文 API Key**（尚未加密持久化），导出会被**拒绝**并写入审计日志。这是为了防止备份文件被分享 / 上传时泄漏密钥。遇到此情况，请先到 API 设置把密钥改为加密状态或清空，再重新导出。
- **建议频率**：
  - 每次进行「批量删除 / 大版本升级 / 改关键配置」前，导出一份。
  - 定期（如每周）导出到云盘或外置磁盘，与本地数据隔离存放。

## 3. 恢复 / 回滚（如何回到备份时点）

**入口**：设置 → 数据管理 → 全量备份与恢复 → `导入备份`

1. 在文件选择框中选入此前导出的 `.json` 或 `.enc.json` 文件。
2. 若选的是**加密备份（`.enc.json`）**，需主密码已解锁才能解密导入；明文备份无需。
3. 选择**冲突处理策略**（见下）。
4. 点击确认后，应用弹出「导入结果」统计弹窗，并自动刷新角色卡与 Persona 视图。

### 三种冲突策略语义

| 策略 | 对「备份有、当前也有（同 ID）」的数据 | 典型用途 |
|------|--------------------------------------|----------|
| **覆盖（默认）** | 用备份版本**覆盖**当前版本 | **回滚到备份时点**：把整库拉回备份当时的状态 |
| **跳过** | 保留当前版本，不写入 | 只补充备份里新增的、当前缺失的部分 |
| **合并** | 保留当前，仅追加备份中新增的 | 合并两台设备的数据，不破坏当前已有 |

> **回滚到过去某一时点的正确做法**：用当时导出的备份文件 + 选择「覆盖」策略导入。导入后，所有与备份同 ID 的数据都会变成备份时的状态。

### 注意事项（导入后视图刷新）

导入逻辑会自动刷新**角色卡**与 **Persona** 视图；但**对话 / 世界书 / 群聊**若当前页面已打开，可能不会立即刷新。建议导入后：
- 重新进入对应页面（如切到别的角色再切回来），或
- 直接重启应用，确保全部数据视图一致。

## 4. 灾备演练 Runbook（建议每季度 / 每次大版本升级前做一次）

灾备演练的目的是**验证你的回滚路径真的可用**，而不是等出事才发现备份无法恢复。

1. **建立基线**：在设置 → 数据管理 导出当前全量备份，命名为 `B0.json`，存到隔离位置（云盘 / 外置盘）。
2. **制造变更**：故意新建一个角色、或删除一条对话、或修改某个世界书条目，制造「与 B0 不同」的状态。
3. **执行回滚**：用 `B0.json` + 「覆盖」策略导入。
4. **校验**：
   - 角色卡列表应与 B0 时点一致（新建的角色消失 / 删除的回来）。
   - 对话 / 世界书 / 群聊内容应与 B0 一致（必要时重启应用后再核对）。
5. **归档记录**：在备份同目录记一笔 `{日期} 灾备演练 基线B0=<文件名> 校验=通过/失败`。

> 演练基数建议保留最近 3 份（如 `B0 / B1 / B2`），形成滚动快照，可回退到不同历史时点。

---

## 5. 跨设备迁移

1. 源设备：设置 → 数据管理 → 导出备份（建议主密码解锁后导出 `.enc.json`）。
2. 将备份文件拷贝到目标设备（U 盘 / 云盘 / 局域网）。
3. 目标设备：设置 → 数据管理 → 导入备份，选择该文件（加密备份需目标设备设置**相同主密码**并解锁后导入）。
4. 用「覆盖」策略完成迁移；目标设备重启后核对数据完整。

---

## 6. 关键注意事项汇总

- **主密码即备份密钥**：加密备份（`.enc.json`）只能由**相同主密码**解密导入。主密码遗忘 = 加密备份**永久无法恢复**，请务必牢记主密码（应用不提供主密码找回）。
- **明文密钥禁令**：存在明文 API Key 时拒绝导出，先处理密钥再备份。
- **导入后视图刷新**：对话 / 世界书 / 群聊导入后建议重启应用确保一致（见 §3）。
- **备份格式版本**：`BACKUP_VERSION = "1.0"`。跨大版本恢复时应用会校验 `version` / `exportedAt` 与数组字段；不兼容的大版本升级请以应用迁移提示为准。
- **审计日志**：导出 / 导入均写入审计日志（设置 → 数据管理 → 导出审计 JSON 可查），仅记录操作摘要（如导出数量、导入增/改/跳计数），**不含任何数据内容**。
- **不要手工拼装备份 JSON**：备份文件结构见 §7，仅供理解；真实演练请使用应用导出的真实文件。

## 7. 备份文件格式（结构概览，仅供理解）

```json
{
  "version": "1.0",
  "exportedAt": "2026-08-17T08:30:00.000Z",
  "sourceEnv": "tauri",
  "characters": [ { "id": "...", "name": "...", "...": "..." } ],
  "chats": [ { "id": "...", "characterId": "...", "messages": [ "..." ] } ],
  "lorebooks": [ { "id": "...", "name": "...", "entries": [ "..." ] } ],
  "groupChats": [ { "id": "...", "name": "..." } ],
  "personas": [ { "id": "...", "name": "..." } ],
  "settings": { "theme": "dark", "...": "..." }
}
```

`exportedAt` 为导出时间 ISO 字符串，`sourceEnv` 标记来源（桌面 `tauri` / Web `web`）。导入时会校验 `version` 与 `exportedAt` 为字符串、各数据数组字段为数组、settings 为对象，格式非法会被拒绝并给出具体错误。
