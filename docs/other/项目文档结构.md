### 一、 项目规划与需求阶段

这个阶段的文档决定“做什么”以及“为什么做”。

1. **项目立项报告 / 商业需求文档（BRD）**：阐述项目背景、商业价值、预期收益、预算和风险评估，用于说服管理层批准项目。
    
2. **市场需求文档（MRD）**：面向市场，分析目标用户、竞品、市场机会和产品定位。
    
3. **产品需求文档（PRD）**：最核心的文档之一。详细描述功能需求、用户故事、业务逻辑、交互流程、边界条件和验收标准。
    
4. **需求规格说明书（SRS）**：偏技术侧的需求定义，将PRD转化为系统功能和非功能需求（性能、安全、兼容性）。
    
5. **可行性分析报告**：评估技术、经济、法律和操作层面的可行性。
    

### 二、 设计与架构阶段

这个阶段的文档决定“怎么做”。

1. **系统架构设计文档（SAD）**：描述系统的整体架构、技术选型、模块划分、分层设计、部署拓扑图。
    
2. **数据库设计文档**：包括ER图（实体关系图）、数据字典、表结构定义、索引设计和数据迁移方案。
    
3. **接口设计文档（API文档）**：定义前后端、微服务之间的接口规范，包括请求方式、URL、参数、返回值、错误码。通常使用 Swagger/OpenAPI 或 Postman 维护。
    
4. **UI/UX 设计规范与原型图**：界面设计稿、交互说明、组件库规范、用户流程图。
    
5. **详细设计说明书（DDD）**：针对核心复杂模块，描述具体的类图、时序图、算法逻辑和核心代码结构。
    

### 三、 开发与实现阶段

这个阶段的文档用于指导编码和团队协作。

1. **代码规范与开发手册**：统一团队代码风格、Git 分支管理策略、Code Review 标准。
    
2. **版本发布说明（Release Notes）**：每次迭代或上线时，记录新增功能、修复的Bug、已知问题。
    
3. **开发进度报告 / 迭代报告**：每日站会记录、Sprint 评审报告、燃尽图。
    
4. **技术评审记录**：架构评审、代码评审、安全评审的会议纪要和结论。
    

### 四、 测试与质量阶段

这个阶段的文档确保“做得对不对”。

1. **测试计划**：测试范围、测试策略、资源安排、风险评估。
    
2. **测试用例（Test Cases）**：覆盖功能、边界、异常、性能场景的具体操作步骤和预期结果。
    
3. **测试报告**：记录测试执行结果、Bug 统计、缺陷分布、遗留问题及上线建议。
    
4. **性能测试报告 / 安全测试报告**：针对高并发、漏洞扫描、渗透测试的专项报告。

5. **「评审建议 → 门禁」登记表（本仓库强制）**：任何评审（跨端评审、SOP 评审、安全评审等）收尾时**必须**输出一张登记表，逐条标注每条建议的归宿，**未填完不算评审完成**。

   | 建议 | 归宿 | 命令 / 理由 |
   | --- | --- | --- |
   | （建议内容 + 编号） | 已转门禁 / 未转门禁 / 不适用 | 已转：附 `npm run check:xxx`；未转：附为何暂不转 |

   **动因**：本仓库实测「评审建议 → 门禁」转化率仅 1/6 —— 绝大多数防回归措施停留在文档层，同类缺陷会静默复发。参见 `docs/fixes/web-sop-review-2026-09-18.md` 第六节的转化登记表。
    

### 五、 部署与运维阶段

这个阶段的文档确保“上线后能稳定运行”。

1. **部署文档 / 运维手册**：环境配置、依赖安装、部署步骤、回滚方案、CI/CD 流水线说明。
    
2. **用户手册 / 操作指南**：面向最终用户，图文并茂地说明如何使用产品。
    
3. **系统维护手册**：日常巡检、日志查看、备份策略、故障排查指南。
    
4. **应急预案 / 灾备方案**：应对宕机、数据丢失、黑客攻击的紧急处理流程。
    

### 六、 项目收尾与合规阶段

1. **项目总结报告**：复盘项目得失、目标达成情况、经验教训。
    
2. **验收报告**：甲方或业务方确认项目交付物符合要求的签字文件。
