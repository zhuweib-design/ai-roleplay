把手机端从"能用但难用"修到"能正常用"，并把四类已量出的问题闭环：设置分类点不到、群聊消息区塌陷、键盘弹起输入条出视口、焦点逃逸。桌面端守成不动。

- **缺陷修复**：MOBILE_PLAN 批次 0（六项）、批次 1（组成层）、批次 2（导航与形态）。
- **交互优化**：触摸目标 44px 落地（批次 3）、guide 移动端入口、市场叙事降级。
- **重构**：OPT_PLAN 批次 3（专项 B 角色↔世界树绑定）、批次 4（专项 A1 导出落点回显）。

| 字段 | 要求 | 反例（不许这么写） |
|---|---|---|
| 状态 | 已完成 / 进行中 / 未开工 / 阻塞（阻塞须写阻塞源与解除条件）/ 挂起待外部条件 | "差不多了" |

| 解决 | 对应上面的问题，写具体手法；不同问题分行对应 | "已修复" |
| 门禁 | 该轮**实跑读数**，必须带数字。没跑就写"未跑" | 留空 / "应该没问题" |

##### 2026-10-18 · A11 角色卡点击行为 → 定乙方案

- **背景**：甲（整卡直进对话）快一步，但编辑入口只能靠长按，不知道长按存在的人等于没有入口；乙（点卡开详情抽屉）四个动作有地方放，但多一步且与"一屏一个主动作"打架。

- **保留**：原文档"甲 + 卡面留一个动作"的倾向未被采纳，但保留在 `MOBILE_PLAN` §6 作为取舍依据。

### 6.5 复盘沉淀（跨任务复用）

**A7 新增的五条（都是会在后续页面上重演的）**：

1. **scoped 样式会压过全局原语**。`.group-body[data-v-x]`(0,2,0) > `.m-swap`(0,1,0)，所以"加一个类就生效"是错觉——`display` 必须由页面自己在媒体块里写，全局原语只管 `[data-level]` 的显隐。A9/A10/A11 接 `.m-swap` 时都会遇到同一件事，别再调试一遍。
2. **`router.replace` 是整体覆盖 history.state**。任何"自己压一层 history"的代码都必须排在路由导航完成**之后**，否则标记被冲掉、返回时先遇到一条空记录。
3. **`<Xxx :title>` 会撞上原生 title 守卫**（`tests/accessibility/no-native-title.test.ts` 只豁免 `<Modal>`）。组件要表达"对话框标题"时叫 `heading`，别叫 `title`。
4. **`display:none` 的元素仍在 DOM**。e2e 里表达"这一级不存在"要用 `toBeHidden()`，用 `toHaveCount(0)` 必红——这条在两级互换类改造里会反复出现。
5. **形态改造要重新走一遍所有进入路径**。群聊的"建群后停在列表级"不是写代码时能想到的：它属于"入口 × 新形态"的组合遗漏。改完组成层，把所有能进这个页面的入口（列表点击 / 新建 / 深链 / 刷新 / 从别页返回）各走一遍，比读代码可靠。

**写断言时踩到的两个坑（记下来防复发）**：

1. **"可达"≠"同时在视口内"**。0-1 最初断言"7 个分类的右边界都在视口内"，三档全红——但那不是缺陷：7 个胶囊内容宽 444px 本就大于 390 视口，**横向滚动条是设计形态**。真正的缺陷是容器自身被撑到 444px、滚动条落到屏外 ⇒ 够不着。改判据为两段：① 容器在视口内（滚动条够得着）② 每项 `scrollIntoViewIfNeeded()` 后完整落在视口内且中心点命中自身。
2. **抽屉断言必须先验证抽屉真的打开了**。0-6 第二条最初用 `.panel-toggle-btn` 打开，遮罩没激活 ⇒ "焦点还在主区"被误判成"inert 没生效"。改为复用 `mobile-layout.spec.ts`（S-4）已验证的 `.mobile-menu-btn[aria-label="打开角色列表"]`，并等 `transform` 归零（动画中间态会拿错）。

## 7. 大文件拆分专项（R 类 · 2026-10-18 立项）

> 与 A/B/C 类的关系：A/B/C 是"修到能用 + 重构体验"，R 类是**结构债**。R 类不动行为、只动组织，所以它**不能与 A 类并行**（A 类正在改同一批文件），也不在 M1–M6 的里程碑里。开工前置条件见 §7.6。

### 7.1 为什么单开一项

### 7.4 拆分单元设计（以 R1-1 为例说明切法）

切法固定为五条，后面 23 个文件都按这五条套：

1. **模板块按功能边界切**，切出来的组件 props in / emit out，不直接读 store（否则只是把耦合挪了个位置）。
2. **样式随组件走**：scoped 样式按选择器前缀归组后整块搬走，主文件只留布局骨架的规则。
3. **脚本按职责切**：纯函数与状态机进 `useXxx.ts`；涉及 store 的读操作留在视图，写操作进 composable。
4. **Modal 独立成文件**：每个 Modal 自带表单状态，父级只接 `@submit` / `@close`。
5. **props 传递深度 ≤2 层**（视图 → 区块 → 卡片）。到第 3 层就改写：
   - 要么把那一层改成直接读 store（读操作，不写）；
   - 要么用 `provide/inject` 一次注入整组上下文（写操作多、且同一子树共享时）。
   **为什么必须现在定**：R2 之后会出现"视图 → 面板 → 区块 → 卡片"四层，props 逐层透传会造出一堆"只为了转发而存在的 props"，读起来比原来的大文件更累——那是把一个问题换成了另一个问题。

### 7.6 验证方式（每个文件拆完必跑，缺一条不算完成）

| 门禁 | 判据 | 为什么这条对这一项有意义 |
|---|---|---|
| `wc -l` 核对 | 主文件 + 新文件总行数 = 原行数 ±12% | 偏差超 12% 说明搬错了块或漏搬（样板开销约 8%） |
| `vue-tsc --noEmit` | 0 错误 | props/emits 类型是拆分最易断的地方 |
| `npm run lint` | 0 errors | 未使用 import、未定义变量 |
| `npm run i18n:check:strict` | 通过 | 模板搬进子组件后若漏 `t()` 会变成硬编码中文 |
| `npm run check:css-conventions` | 5/5，`!important` 不增 | scoped 样式搬迁后选择器特异性可能变化，守卫会咬 |
| 相关单测 | 该文件对应测试全绿 | 先跑测试再拆（测试即契约），拆完再跑 |
| 对应 e2e spec | 绿 | 例如拆 `GroupChatView` 要跑 `group-chat-flow` + `group-composition` + `group-header-narrow` |
| `npm run check:file-size` | 通过 | 拆完的文件要把白名单里的登记行数改小；降到 800 以下则整条删掉（§7.10） |
| 截图对比 | **批次级，不是文件级**：`node scripts/ui-shot.mjs` 在批次开头与结尾各一次，只人工比对**该批涉及的路由** | 原稿写"每个文件前后各一次"不可行：24 个文件 × 2 次 × 26 张 = 1248 张，且基线会被同批其它文件改动污染，比出来的差异归不到具体文件 |
| 全量 `npm run test` | 0 failed | 每个**批次**结束时跑一次，不是每个文件 |

**"行为零变化"的定义与例外**：拆分 commit 里只允许出现"移动 + import/export + props/emits 接线"，**不允许出现条件分支、样式数值、文案的改动**。

允许一个例外，但必须显式登记：**为保持视觉一致而必需的选择器补位**。scoped 样式随组件搬走后，原来由父级选择器命中的元素可能失配（例如父级 `.group-header .action-btn` 到不了子组件内部），此时补一条等价的子组件内选择器是必要的。这类改动不算违反零变化，但必须满足两条：

1. commit message 里写明"补位：原选择器 → 新选择器，为什么必须补"；
2. 同批的截图比对里，该路由的像素差异必须为零（补对了才没有差异）。

一旦混进真正的行为改动（多一个 `v-if`、改一个间距值），回滚粒度就毁了——这也是"每个文件一个 commit、批次内不 squash"的原因。

11. **"六个字段段共用一个对象"要靠 `defineModel`，不能靠对象 prop 变异**。`form` 在子组件里是 `defineModel<FormState>('form', { required: true })`：宿主 `v-model:form="form"` 传下来的是同一个响应式对象，子组件改属性即改宿主，但**不需要 emit**（从未重新赋值 `form.value`）。换成"`defineProps<{form: FormState}>()` + `v-model="form.name"`"会直接踩 `vue/no-mutating-props`（`flat/recommended` 里是 error）。另注：`defineModel` 的 `update:form` 事件在本模式下一次都不会触发——这不是遗漏，是这个模式的正常形态。
12. **`isDirty` 的 watch 必须留在宿主、且挂在初次填表之后**。把它收进 composable 会改变执行顺序：深链进来时角色库还没读完，`loadCharacter()` 发生在 watch 注册**之后**，深拷贝填表会被自己的 deep watch 标成"已修改"，于是编辑页一按取消就弹"未保存"确认——一个旧代码没有的回归，而且**现有单测抓不到**（没有用例断言"刚打开就取消不该弹窗"）。这类"顺序即语义"的代码，拆分时**只能平移不能上提**。
13. **守卫基线分两类，迁移方式不同**。R1-5 撞的是"读哪个文件"（源码漂移守卫，改路径、判据不变）；R2-1 撞的是"登记表"（`control-size` 的按文件字面量数、`token-guard` 的按文件裸引用数、`file-size` 的白名单），这三者要**改基线并写归属说明**，且**总数必须不变或下降**（本次 control-size 62→62、token 77→77、file-size 22→21）。看到"新文件 +N / 旧文件 −N"先别急着当成新增缺陷，先核对总数。

**R2-2 新增的两条结构结论（补充 §7.8.1）**：

14. **基类跟谁走，取决于"这个子组件会不会被别处引用"，不取决于"它是不是子组件"**。R1-4/R2-1 拆出的是通用组件（设置面板、角色编辑器 section），别处可能引用，所以必须自带基类；R2-2 拆出的五个 Panel 只在这一页出现，把 `.btn`/`.badge`/`.form-group` 复制六份只会让 945 行样式变成 1600+ 行。做法：共享基类留宿主，写成 `.version-view :deep(.btn)`（`ChatMain` 的 `:deep(.msg-bubble)` 已有先例）。**判定问句**：把它移到别的页面时，它还需要这些样式吗？需要 → 自带；不需要 → 留宿主。
15. **`css-equiv` 对 `:deep()` 前缀化无能为力，用"括号配平还原"补一次证据**。前缀化会让每条共享规则在原始差集里显示为"丢失"（R2-2 是 41 条）。验证手法：把 `.version-view :deep(X)` 用括号配平临时还原成 `X` 写进 `dist-norm/`（gitignore + eslint 双覆盖），再跑一次差集——R2-2 实测 **144 → 0 丢失**，剩下那条 `.sr-only` 是死副本（`base.css` 的全局版每条带 `!important`，本页副本一直被压制）。**别把这次"丢失 41"当成搬漏**，也别为了凑绿去改守卫的判定。
16. **有测试依赖组件形态时，先保形态再谈统一**。本页 Toast 没迁到全局 `toast-service`（R1-4 那批迁了）：`deep-link-waits-character-library` 把 `Toast` 换成桩、从 `message` 断言"角色不存在"，迁走就没得断言。这类"技术债清单上的统一"要排在有断言保护的地方之后。

17. **「子组件各自调 composable」与「必须共用同一份状态」不矛盾，判据是"有没有可变状态"**。R2-1 六段必须共用一个 `form`（跨字段校验 + 一次性补丁），所以用 `defineModel` 传对象；R2-3 八段各自调 `useContextPanel()`，因为里面**全是纯投影 + 写 store**，多实例化只是多算几次 computed，数据仍只有 store 一份。分界线：**composable 里只要有一个 `ref` 被两段读写，就必须上提**——`schemaOpen` 正是这个原因留在 `ContextStatusSection` 内部而不是进 composable。
18. **「面板不挂 XX」这类否定断言要扫目录，别逐个列文件**。R2-3 把 `ContextPanel` 拆成 1+8 个文件后，原来那句"ContextPanel 不应挂载 StatusHud"只守住了宿主——新拆出来的八个文件成了盲区（谁在里面补一条状态条，守卫看不见）。改成 `readdirSync(context/)` 扫整目录 + 断言文件数下限，以后再加 section 自动覆盖。同理适用于零 `v-html` / 零 `innerHTML` 白名单。
19. **计划里的"拆成 N 件"是估算，不是约束**。R2-3 计划写"3 件 / 690"，实际拆成 8 段——原文件本来就是**九个并列 section**，按 section 切是唯一天然边界；硬凑成 3 件只会把不相干的两段塞进同一文件。判据始终是"边界在哪"，件数是结果。回填时把计划值与实测值并列写清，别偷偷改计划。

### 7.8.2 R-P 批：共享原语化（`styles/primitives.css`，2026-10-19）

**为什么能安全全局化：scoped 特异性**

### 7.10 防回长守卫（`check:file-size`）

> §7 是 20–30 人日的投入。没有门禁的话，拆完的 92 个文件半年后会重新长回去——这件事不能靠"下次注意"，只能靠会失败的检查。

**脚本**：`scripts/file-size-guard.mjs`（零依赖，与 `important-guard` / `token-guard` 同一形状：白名单 + 棘轮）
**命令**：`npm run check:file-size`（= `--strict`）；`--list` 只看白名单现状
**CI**：`.github/workflows/ci.yml` 的 `quality-gates` 里，紧跟 `check:css-conventions` 一步

**四条判定**：

| 情形 | 结果 |
|---|---|
| 不在白名单、>1000 行 | **失败**（新长出来的大文件） |
| 不在白名单、800–1000 行 | 警告（进观察名单，不阻断，但评审要说明） |
| 在白名单、当前行数 > 登记行数 | **失败**（拆过的文件又长回去了） |
| 在白名单、当前 ≤800 行 | 通过 + 提示把条目删掉（它的债已经还完） |

**为什么白名单锁"登记行数"而不只锁"存在性"**：只锁存在性的话，文件从 1000 长到 2000 也算通过。§7 的价值全在"它会一直变小"，所以必须对增长有反应。

**登记值上调的条件（2026-10-18 补，A11 第一次撞到）**：棘轮防的是"无声漂移"，不是禁止所有增长。白名单文件因**新增功能**而变大是正常演进，处理方式是——在守卫脚本里显式上调登记值，并在旁边注明"哪一轮功能 + 多少行 + 何时回收（指向 R 类编号）"；只在 commit 里改数字不写原因是违规。**数据文件例外**：i18n 字典标 `ratchet: false`，完全不参与增长判定——每次加 i18n key 都合法，对它套棘轮只会让守卫频繁假红、进而被绕过（比没有守卫更糟）。

**白名单现状**：24 条 = §7.2 的 2 个 i18n 字典 + §7.3 的 24 个目标文件中尚未拆的 22 个（R1-2、R1-3 已销账两条），每条都带 `reason`（未写理由的新增条目评审直接打回）。

### 7.11 共享原语复用守卫（`check:primitives`）

> §7.8.2 把 `.btn` 提到了全局。但没有门禁的话，下一次拆分照样会把 `.btn` 复制进新组件——和 §7.10 防"文件回长"是同一类问题：**投入必须能自锁**。

**脚本**：`scripts/primitives-guard.mjs`（零依赖，与 `file-size-guard` 同一形状）
**命令**：`npm run check:primitives`（= `--strict`）；`--list` 看各文件当前计数
**CI**：`.github/workflows/ci.yml` 的 `quality-gates` 里，紧跟 `check:control-size` 一步
**测试**：`tests/tooling/primitives-guard.test.ts`（5 条）

**三条判定**

| 情形 | 结果 |
|---|---|
| 组件里出现与 `primitives.css` **逐字同值**的 `.btn` 族规则 | **失败**（在复制全局已有的东西） |
| 某文件 `.btn` 族规则数 > 登记值 | **失败**（长回去了） |
| 某文件 `.btn` 族规则数 < 登记值 | 通过 + 提示下调登记 |

**为什么第 1 条按"逐字同值"判，而不是"选择器存在就报"**

14 个文件里的 `.btn` 有 6 个视觉变体，它们**本来就该分开**（padding 6/8、`--radius-md`/`--radius-sm`、`--card`/`--card-elevated`、rem 体系）。按"存在即报"会逼着人合并本来不同的样式，或者给守卫加一堆豁免——两种结局都比没有守卫更糟。守卫只咬"明明没差异却还写了一遍"。

**解析口径的两个坑（都踩过，已修）**

1. **不能整文件找 `@`**：`.vue` 模板里的 `@click` / `@/stores/...` 也带 `@`，当成 at-rule 起点会把后面大段内容吃掉——行号还在、规则没了，静默漏检。做法：先取 `<style>` 段，且只认 `@media|supports|keyframes|font-face|layer|container|starting-style|property|scope`。
2. **必须剥掉 at-rule 块再判同值**：媒体查询里的 `.btn-label { font-size: 16px }` 是有意的窄屏覆盖，不是复制全局。不剥会误报，然后被人加进豁免名单，守卫就废了。

**第 4 条断言是负向能力测试**：往文件里塞一条同值规则，守卫必须真的变红。前三条只证明"跑通了"，只有这条证明"咬得住"——本轮就是靠它发现字段名写错（`b.sel` vs `r.selector`）导致恒等于 0 命中、守卫一直假绿。

**例外表**：`EXEMPT` 只登记"逐字同值但不能删"的情况，每条必须写原因。目前 1 条（`CommunityMarketView` 的 `.btn-primary`，层叠顺序问题，见 §7.8.2）。空白原因视为无效登记。
