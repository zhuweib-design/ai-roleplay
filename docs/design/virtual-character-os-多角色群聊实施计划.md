# Virtual Character OS 多角色与群聊实施计划

日期：2026-09-23
分支：`codex/runtime-core-baseline`
状态：批量角色、浏览器群聊、PostgreSQL 群组公共回合、成员 CAS 和本地待提交重试已接入；生产认证、服务端可靠队列和最终部署验收仍待完成。

## 现状与缺口

- 角色按 ID 独立保存，单聊可切换多个角色；聊天 Store 将 UI 角色映射为稳定 Runtime UUID，并按角色与会话缓存集成。现有单聊按角色切换。现已增加 `POST /v1/runtime/characters/batch` 逐项创建（1 至 50 项、稳定 ID、重复 ID 拒绝、已存在和编译失败逐项报告），租户内角色列表与游标分页已加入 Runtime API；角色页已支持一次导入最多 50 个 V2 JSON、逐文件进度和 Runtime 失败重试，待重试 ID 按资料档案持久化。
- 群聊 UI 已允许 2 至 8 个角色、自然轮换与指定发言，并在本地保存群组和消息。现已由 `GroupChatView.vue` 调用真实 `ChatManager` 流式生成，当前发言角色接入独立 Runtime Context 和 Event，并有浏览器双角色测试；其他成员的公开旁听 Event 已按角色独立写入；新增服务端事务协调器已实现公共 Turn 与各成员 Event 原子提交，但当前浏览器群聊尚未切换到该边界。
- PostgreSQL `conversations` 绑定单个 `character_id`，`events` 也按单角色保存。不能把一个群聊伪装成某个角色的私有会话，否则会混淆成员、证据和租户边界。
- Web/Tauri `StorageAdapter` 没有跨进程原子比较写入。进程内同适配器实例的初始化和提交已加锁；服务端的强并发保证依赖 PostgreSQL 事务与唯一约束。

## 阶段一：批量多角色资源

1. 在 Runtime API 定义租户内角色列表和批量创建契约。批量请求限制条数（建议每批最多 50），每项须有稳定的角色 ID 或由服务端返回生成的 ID；拒绝请求内重复 ID 和跨租户角色 ID。服务端租户只由认证边界注入，不信任客户端 `tenantId`。
2. 批量语义明确为逐项提交和逐项结果，而非伪装成全有或全无事务。结果包含输入索引、角色 ID、创建或已存在或校验失败状态、可重试错误；重复请求不得覆盖版本 0 的已有角色。局部失败可用同一组稳定 ID 安全重试。若未来需要原子批次，另设显式原子模式与单一 PostgreSQL 事务。
3. PostgreSQL 查询用租户过滤、稳定排序、游标分页；Web/Tauri 快照适配器按 Runtime 命名空间前缀枚举已有快照，不依赖新建索引，兼容旧快照。结果按租户过滤，列表只返回角色定义，不泄露其他租户的原始对话和记忆。
4. UI 增加批量导入或创建入口、逐项进度与失败重试，不改变已有单角色流程。角色切换后验证 Context、Event、记忆和会话均按角色隔离。

验收：同租户一次创建多个不同角色；重复批次只报告已存在而不覆盖；混合有效和无效项按契约返回；跨租户列表和读取不可见；两实例并发相同 ID 仅创建一条；本地刷新后索引与快照一致。

## 阶段二：群聊真实模型编排

1. 将 `simulateAiReply()` 替换为可测试的群聊协调服务。输入为群组、用户消息、当前成员和模式；根据自然或指定策略选择发言者，并使用真实 `chat-manager`/API 客户端生成回复。指定模式需保存待发言角色，而非仅显示一次提示；重入、取消、流式失败和群组切换不能改写另一群组的最后一条消息。
2. 模型请求由当前发言角色的角色卡、该角色私有 Runtime Context、群组公开消息窗口及成员名单组成。不得把其他角色私有记忆直接注入当前发言者提示词。设置消息和 Token 上限，明确群组系统消息与首消息的发言者归属。
3. 为群组定义稳定 UUID、成员身份和有序公共 Turn。PostgreSQL 新增租户隔离的群组、成员与群组 Turn 表，群组 Turn 保留说话角色 ID 和顺序；单角色 `conversations`、`events` 继续只承载对应角色的 Runtime 状态，增加群组 Turn 与角色 Event 的证据关联，不复用其他角色的私有 Turn。
4. 首先把实际发言角色的回复作为其 Event 幂等提交；再为其他成员建立明确的“观察到群内发言”事件投递规则，使每个成员的状态有独立、可回放的事件流。服务端按固定角色 ID 顺序锁定并原子写入公共 Turn、参与成员 Event、投影、Snapshot 和 Audit；本地模式通过持久化待投递队列重试，并显式呈现非原子状态，不能宣称与服务端同等事务保证。
5. 新增按群组和角色的 Context 查询；群组读取需同时验证租户、成员资格与当前状态。成员加入、退出、临时 NPC 归档及历史消息保留均有确定语义，不把历史私有上下文暴露给新成员。

验收：2 至 8 人真实模型群聊、自然与指定发言、每个角色独立 Context 与 Event、稳定群组 Turn 关联；相同请求重试不重复消息/状态；跨租户和非成员访问拒绝；并发群组 Turn 顺序与角色版本连续；中途失败不产生服务端半提交。

## 阶段三：验证与上线边界

- 单元测试覆盖批量契约、角色隔离、群聊选择、提示词隔离、取消/重试、回放确定性和异常路径。
- 真实 PostgreSQL 16 隔离 Schema 测试覆盖批量并发、成员变更、群组 Turn + 多角色 Event 原子性、证据归属与审计；HTTP 测试覆盖租户边界、错误状态与幂等。
- 浏览器端到端使用可控模型响应，完成多角色创建、群聊真实回复、切换发言者、刷新恢复、不同角色 Context 差异和失败重试；Web/Tauri 分别验证存储行为。
- 每阶段运行全量测试、类型检查、ESLint、Schema 漂移检查、生产构建和 `git diff --check`；记录实际结果。真实网络服务、生产认证、迁移和备份需另行部署验证，不能以 Fetch Handler 测试代替。

实施顺序：先定契约与迁移，再做批量资源；群聊先完成真实模型编排和客户端隔离，再接服务端群组事务与多角色事件，最后进行浏览器及真实数据库全链路验收。每阶段保留现有单聊路径和回归测试。

## 2026-09-23 群聊编排进展

- 已移除模拟回复，改用当前 API Profile 的模型流。自然轮换和指定发言均能生成真实回复；组内公共历史窗口与发言角色私有 Runtime Context 分开注入。
- 当前发言角色使用独立的 group-{groupId} 会话键记录 Event；模型失败保留用户消息并展示错误，不伪造回复。流式更新按群组和消息 ID 定位，避免切换群组时覆盖他组消息。
- 同毫秒创建群组及用户消息的 ID 碰撞已修复；群聊首消息的原始发言者归属也已修复。浏览器端到端用例覆盖两个角色自然轮换、指定发言、私有上下文隔离和 Event 落盘。
- 这还不是群组服务端原子事务：群组公共 Turn、跨成员 Event 原子提交、成员/租户持久化授权仍未实现，不能将现有单角色 Event 写入误报为多角色事务。

## 2026-09-23 旁听事件扩展

## 2026-09-23 群聊统一 HTTP 入口与创建安全修复

### 本轮实现

- 统一 PostgreSQL Fetch Handler 分派群聊路由；单角色路由保留原行为。客户端与群聊 Handler 共享独立契约模块，不再因错误类导入 PostgreSQL 协调器。
- 恢复严格创建幂等语义：同 ID、同名称、同成员集合的请求可以重试；不同定义返回 GROUP_CONFLICT，不隐式更名、删除成员或恢复已退出成员。已归档群组拒绝创建重试。成员更新必须调用显式接口。
- 创建事务先处理群组，再按固定 ID 顺序锁定角色，与公共回合提交一致，移除先角色后群组的反向锁定路径。
- 修复本地自然轮换模式遗漏旁听 Event 的分支；指定发言者清除与旁听写入分开判断，并要求成功回复和有效消息 ID。
- 拒绝 turns/extra、context/extra 等无效路径；Context 校验字符串、有效时间及非负安全整数限制，保留零数量语义。

## 2026-09-23 远端成员限定上下文与真实 HTTP 验证

## 2026-09-23 远程群聊待提交回合可靠重试

### 本轮实现

- Chat Store 增加远程群聊待提交队列，键为本地群聊 ID 与逻辑回合 ID；同键重试只增加尝试次数和错误信息，不覆盖原始用户消息、发言角色或模型回复。

- 应用启动完成存储初始化后恢复队列；群聊页展示当前群组的待提交数量，并提供显式重试按钮。重试成功删除队列项，失败保留并增加尝试次数；群聊删除时清理对应队列。
