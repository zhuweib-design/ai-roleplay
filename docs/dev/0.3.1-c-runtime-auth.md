# 0.3.1 C 阶段：Runtime 认证与租户边界

完成日期：2026-09-26

## 交付范围

- Runtime HTTP 与群聊 HTTP Handler 支持宿主注入可信 `principal`。
- 强制认证模式下，除健康检查外的请求没有有效 principal 时统一返回 `401 AUTHENTICATION_REQUIRED`。
- principal 的 `tenantId` 覆盖客户端请求体和查询参数中的 tenant，客户端自报 tenant 不能扩大访问范围。
- 角色按 ID 读取和构建 Context 时增加租户校验，跨租户访问返回 `403 TENANT_FORBIDDEN`。
- 群聊使用静态租户绑定时，认证 principal 的 tenant 不匹配会被拒绝。
- 认证宿主可以注入成员授权器，授权失败返回 `403 MEMBER_FORBIDDEN`；Runtime 核心不绑定具体账户系统。

## 代码落点

- `src/runtime/runtime-auth.ts`：principal、认证器、成员授权器和统一错误响应。
- `src/runtime/runtime-http.ts`：角色 Runtime 的认证、租户绑定和成员授权接线。
- `src/runtime/runtime-group-http.ts`：群聊 Runtime 的认证、静态租户匹配和成员授权接线。
- `src/runtime/runtime-api.ts`：角色读取与 Context 构建的租户校验。
- `tests/runtime/runtime-http.test.ts`、`tests/runtime/group-runtime-http.test.ts`：匿名、跨租户读取、租户不匹配和成员授权测试。

## 边界说明

成员授权器是服务端部署方的注入点。当前仓库提供可信 principal 到授权器的完整调用边界，但不会假设具体登录 Provider、会话格式或成员表结构；这些内容在真实部署接线时由宿主实现。
