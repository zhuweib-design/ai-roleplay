# AI 酒馆 1.1.0 发布说明

发布日期：2026-10-16
上一版本：1.0.0（2026-09-27，首个稳定版）

## 版本定位与为什么是次版本

1.0.0 冻结的是**数据与运行时契约**：核心数据契约、Runtime Event/Reducer、备份恢复、资源许可证、
PostgreSQL 迁移边界。1.1.0 没有触碰其中任何一条——没有新增数据库迁移，没有删除或改语义的字段，
旧角色卡、聊天、世界书、故事、设置与备份全部按原规则读取。

新增的都是能力与界面（手机端可用化、心理活动叙事、注入可见化、Token 预算推导、安卓出包、工程护栏），
按本仓库 `CHANGELOG.md` 顶部写的规则"主版本用于稳定版契约，次版本用于功能发布，修订版本用于兼容性修复"，
它既不是补丁（内容量远超修复），也不是主版本（无破坏性变更），所以是 **1.1.0**。

版本号同步的四处：`package.json`、`package-lock.json`（根包两条 `version` 字段，第 3 与第 9 行）、
`src-tauri/tauri.conf.json`、`android/app/build.gradle`（`versionName "1.1"`，`versionCode` 1 → 2，
安卓要求单调递增才能覆盖安装）。

**应用内看不到这个版本号**：设置 → 关于那一行读的是组件里的 `appVersion`，它声明后从未被赋值
（`SettingsAboutPanel.vue:8` 与 `:31`），所以界面上恒定显示"版本：—"。这是存量缺陷，不是这版改坏的，
本批文档只把它写明、不冒充"运行时读到的版本"。接上它需要构建期常量（`vite.config.ts` 的 `define`
里现在只有 `__NATIVE_SHELL__`）＋一条断言，留作发布后的小改动。

## 这一版用户能看见的变化

手机端聊天页从"能打开"变成"能用"：

- 输入条：发送键移到右边、静止态只有一行高、打字自动长高、超过 6 行在输入区内部滚动而不是把页面顶长；
  触屏上回车是换行（软键盘没有 Shift），发送靠右边那个按钮；桌面上仍是 Enter 发送、Shift+Enter 换行。
- 消息操作：平时不显示任何按钮，长按一条 AI 消息约半秒弹出底部动作条（编辑、复制、朗读、翻译、
  重新生成、删除）；长按期间手指移动会被判为滚动而不弹条；桌面端悬停/键盘聚焦照旧。
- 键盘弹起时输入条跟着抬到键盘上方（安卓壳与网页两处一起改，见"工程"一节）；关掉角色抽屉后
  那 250ms 内遮罩不再吃掉点击与长按。
- 窄屏修复：群聊页头、世界书页头、社区市场页头、设置页数据面板里被压成"一列一个字"的标题与按钮
  全部恢复单行；主 Tab 页底部重复预留的 56px 收回来（约 10% 屏幕高度）。
- 切语言后底部导航立刻跟着变，不再留着旧文案；全新安装的首帧就是最终语言，不再闪一下错语言。

心理活动（旁白）：

- 模型可以在回复里写 `⟦ … ⟧`，这段会显示在气泡**外面**，排版与正文不同（13px、次级色、左侧竖线），
  读起来是"这个角色在想什么"而不是"她说了什么"。
- 设置里可选心理活动里用户自称"我"还是"你"，选择会进提示词并影响生成。
- 群聊用同一套分段；复制、朗读、翻译、导出都会去掉标记，用户拿到的永远是干净文本。
- 编辑消息时文本框仍是可编辑的原文，下面多了一块与气泡同规则的实时预览，并有一句解释标记是什么。

Token 与预算：

- 只配一个真实量（模型最大上下文），输出预算、压缩阈值等全部推导，不再有人工上限旋钮；
  上下文输入框带常用预设（32K / 64K / 128K / 272K / 400K / 600K / 1M）。
- 推理型模型把输出预算全花在"思考"上时，不再返回一个空气泡，而是给一句可操作的提示
  （说明原因并提示调大该模型的最大上下文）。

注入可见化：助手气泡下可展开"本轮注入了哪几条设定"，列出来源世界书、条目标题与命中关键词，
书名可点回世界书页并带返回路径。

安卓分发：一条脚本出包（`node scripts/android-apk.mjs`），debug APK 可装可调试；安装包不再进 git，
改走 GitHub Releases，并有一道门禁阻止安装包/大二进制被提交。

## 数据兼容

- 无新增数据库迁移，无 schema 变更。
- 心理活动标记直接存在消息 `content` 里，因此**旧数据不含标记、照常渲染**；新数据在只读 `content`
  的旁路（复制、朗读、翻译、导出、备份）上统一走 `stripNarrationMarkers`，不会把 `⟦ ⟧` 漏给用户。
- 新增一个 localStorage 键 `aijiuguan.locale`，只是"用户显式选过的语言"的同步镜像，真值仍是
  IndexedDB 里的 `AppSettings.locale`；删掉它下次启动退化为按浏览器语言，不影响任何数据。
- 引导任务只持久化用户意图（跳过/收起），完成态不落盘，因此删角色后任务会自动退回未完成。

## 已知边界与未覆盖项

以下都是"没验/没做"，不是"通过"：

- iOS Safari 的键盘兜底（`--keyboard-inset`）只有按真实数值形状写的单测，本机无 iOS 设备可跑；
  Android 侧"差值恒为 0、不重复抬升"是实测过的。
- 安卓上的导出按钮仍是死按钮：WebView 的 `showSaveFilePicker()` 是 14ms 就抛 AbortError 的桩，
  要修需要写原生插件（走系统 `ACTION_CREATE_DOCUMENT`）。当前 9 处导出统一走 `saveBlob()` 单入口，
  就是为了修的时候只改一处。
- 真实 Provider 的正向链路（一键生成、出图、世界书端到端注入）需要外部凭据，未用离线断言冒充实机通过。
- PostgreSQL 全量迁移与真实库集成只在 CI 侧有服务，本机无 Docker，未在本机复跑。
- 群聊页的心理活动排版在真机量过几何，但整页交互（多角色连续发言时的观感）没有做人工评审。
- `worldEntries` 的死路径为兼容旧备份/导入暂未清理。
- 设置 → 关于的"版本："仍是占位破折号，界面上看不到 1.1.0（原因与修法见"版本定位"一节末）。

## 工程侧值得单独记的三件事

1. 全量 e2e 从"同一套代码 4 worker 随机红 1–3 条"改成稳定全绿：把"一条用例循环整个维度"的两条重规格
   按维度切小（对比度按皮肤、字号按路由分组），并把等待预算按单跑耗时的实测倍数抬高；CI 分片改为
   按单 worker 实测时长分组，并加"每个 spec 恰好属于一组"的对账守卫——新增用例不登记就会在 CI 上静默不跑。
2. 首帧语言：`localeRef` 的初值改成同步求得（用户选过的镜像 > 浏览器语言 > 中文）。改初值当场红 280 条
   单测，原因是测试环境隐式沿用 jsdom 的 `en-US`；按 e2e 早已钉死 `locale: 'zh-CN'` 的先例给单测环境
   补了显式语言声明，红数归零。
3. 一条只在 CI 才暴露的基线漂移：range 滑块的 `color` 从来没被 CSS 设过，取的是 UA 默认 `FieldText`，
   而它随操作系统解析——Windows 上 msedge 与 chromium 都给 `rgb(16,16,16)`，CI 的 Linux chromium 给暖灰。
   修法是让它显式继承主题前景色。教训：**任何在一台机器上生成的像素基线都要注明引擎与系统，
   而"CSS 从没设过的属性"本身就是漂移源。**
