## 3. ⚠️ 遗留项（如实归档，勿当成已完成）

### 遗留 1：L1 情绪词保真不足 —— **阻塞 L1 启用**（最重要）

- **现象**：情绪词保留率 82.75%（去重 81.85%），达不到校验阈值 0.9
  → 严格口径下**端到端节省 0.00%、4/4 全部 fail-open 回退**
- **根因**：`extractiveCompress` 的打分只有 `relevance + salience + 句长`，
  **不含情绪词权重** → 带情绪的句子按约 60% 概率被丢
- **后果（二选一困境）**：
  - 传参（entities/emotionWords）→ 校验不过 → 全部回退，压缩不生效
  - 不传参 → 校验恒通过 → 保护失效
- **修法（三选一，未做）**：① 给打分加情绪词权重（治本，但压缩率会下降）；
  ② 放宽阈值 0.9 → 0.85（治标）；③ 暂不动
- **影响范围**：**L1 默认关闭，暂不影响用户**；但"启用 L1"这个开关目前不能轻易打开

### 遗留 2：编辑消息路径未触发摘要

`editMessage` 会**改写历史**，理论上让既有摘要的 `lastCoveredMessageIndex` 失准。
重新摘要成本较高，且当前无「摘要失效 / 重建」策略，故暂未做。
（`sendMessage` 与 `regenerate` 两条路径已覆盖。）

### 遗留 3：需真实环境的 7 项指标未测

缓存命中率、TTFT p95、设定一致率 ×2、情绪标签连贯率、盲评、BM25 召回耗时。
`opt-eval` 已**全部标注 `requires-real-env`，未编造数字**；`--with-api` 探针已实现，
但当前无 API key，只验证了"正确跳过"路径。

### 遗留 4：本地上下文天花板仍是 4096

`MODEL_REGISTRY` 各模型的 `contextLength` 由 WebLLM 预构建权重决定，均为 4096。
线上已可通过设置页调整（`31c44df`），**本地不受该入口影响**。

## 4. 方法论沉淀（本次最有价值的部分）

### 4.1 核实"某能力是否接线"必须搜两层

只 grep 底层函数名（`decideCompression` / `extractiveCompress`）会**漏掉封装层**，
把"已封装接线"误判为"未接线"。
→ **必须同时搜索「底层函数名」与「其所在模块的高层导出」**。

### 4.2 功能接线必须**两端都验证**

① 数据/能力**从哪来**（生成端）② **到哪去**（消费端的输入）。
只验证一端就宣布完成，得到的是"写了但没生效"。
（摘要就曾漏了 `existingSummary` 这个注入端输入。）

### 4.3 测量工具会暴露"接线不完整"

L1 的两个缺陷（校验恒通过、分母错误）**靠读代码发现不了**（函数签名完全正常），
是 `opt-eval` 跑出「4/4 恒通过」「0 条压缩」才暴露的。
→ **功能做完要用评估脚本验证它真的按预期工作**，而不只是"没报错"。

### 4.4 配套显示不一致 = 主功能的组成部分

`ContextPanel` 硬编码 8192 导致配置 256K 后用量条恒显 100%。
这不是"独立的后续优化"，而是**主功能的一部分** —— 配置改了但可视化没跟上，
用户会以为设置没生效。**发现即同批修，不留作"后续建议"。**

### 4.5 本地模型选型必须先核对 WebLLM 预构建列表

WebLLM 只加载预编译的 MLC 权重，**不是任意 HuggingFace 模型都能跑**。
`Index-1.9B-Character` 就不在列表中 → 注册它会得到一个点不动的开关。
→ 任何本地候选模型，**先查 `mlc-ai/web-llm` 的 `config.ts`**。
